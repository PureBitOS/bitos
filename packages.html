Package repository

BitOS v0.1 has no package manager yet — this page defines the plan from the roadmap: “Simple package format + free GitHub-based package repo.” Everything (code, ISOs, packages) stays on this GitHub account. No domain, no paid hosting.

Status

v0.1 — registry planned, 0 packages shipped

The kernel currently boots → prints → halts. Package support lands after long mode, keyboard, and a basic shell (roadmap steps 1–2).

  • Source of packages: PureBitOS/bitos releases + Pages
  • Distribution: static files over HTTPS (GitHub Releases / raw / Pages)
  • Install story (planned): shell fetches .bit file → verifies manifest → extracts to RAM disk

Planned .bit format (draft)

{
  "name": "hello",
  "version": "0.1.0",
  "arch": "x64",
  "bitos": ">=0.2",
  "entry": "/bin/hello",
  "files": ["bin/hello", "share/hello.txt"],
  "sha256": "<hex>"
}
  • Single archive (e.g. hello-0.1.0-x64.bit = tar/zstd + manifest.json)
  • Manifest holds name, version, arch, min BitOS version, entry point, file list, hash
  • Registry index is a static packages.json served from GitHub Pages

For package authors (draft)

  1. Build a static binary for BitOS x64.
  2. Add manifest.json (schema above) + SHA-256.
  3. Pack as <name>-<version>-x64.bit.
  4. Open a PR against PureBitOS/bitos with the .bit link + manifest.
