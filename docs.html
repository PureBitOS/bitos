1. Requirements

  • nasm — assembles kernel/*.asm to ELF64 objects
  • ld (GNU binutils) — links with kernel/linker.ld
  • grub-mkrescue (+ xorriso) — builds bootable bitos.iso
  • qemu-system-x86_64 — test boot (make run)
  • git — clone https://github.com/PureBitOS/bitos.git

2. Building & running

git clone https://github.com/PureBitOS/bitos.git
cd bitos
make          # nasm + ld + grub-mkrescue -> bitos.iso
make run      # qemu-system-x86_64 -cdrom bitos.iso -display none -serial stdio
make clean    # removes *.o, iso/boot/kernel.bin, bitos.iso

What Makefile does (all 7 kernel/*.asm via pattern rule):

  1. nasm -f elf64 kernel/*.asm -o kernel/*.o (multiboot_header, boot, vga, serial, idt, kbd, shell)
  2. ld -n -T kernel/linker.ld -o iso/boot/kernel.bin ...
  3. grub-mkrescue -o bitos.iso iso

Note: *.o, *.bin, *.iso are git-ignored (see .gitignore). Don't commit build artifacts.

3. Building on Windows

Two supported paths. WSL2 (recommended) gives you the exact Linux toolchain the Makefile expects.

Option A — WSL2 + Debian (recommended)

  1. Install WSL2 and Debian:
    wsl --install -d Debian (reboot if asked, create your Linux user)
  2. Inside Debian, install the toolchain:
    sudo apt update && sudo apt install -y nasm make grub-pc-bin xorriso qemu-system-x86 binutils
  3. Build and run from inside WSL (adjust the path to where you cloned the repo):
    cd /mnt/c/Users/<you>/Documents/bitos
make          # -> bitos.iso
make run      # boots it in QEMU

Option B — Native Windows (no WSL)

  1. Install NASM and QEMU for Windows (or via winget install -e --id NASM.NASM --id SoftwareFreedomConservancy.QEMU), and add both to PATH.
  2. Assemble + boot-test natively:
    nasm -f elf64 kernel\multiboot_header.asm -o kernel\multiboot_header.o
nasm -f elf64 kernel\boot.asm -o kernel\boot.o
qemu-system-x86_64 -cdrom bitos.iso
  3. Linking (ld -n -T kernel/linker.ld) and ISO creation (grub-mkrescue) have no native Windows builds — run just those two steps in WSL2/Git Bash, or do the full build via Option A.

Cleaning: make clean uses rm (works in WSL/Git Bash). In plain cmd.exe use make clean-win instead.

5. Boot flow (v0.3 — shell)

  1. GRUB shows its menu (timeout=-1: no autoboot — pick “BitOS v0.3”, hotkey b) and loads /boot/kernel.bin as a Multiboot2 kernel, jumping to start in 32-bit mode with magic 0x36d76289 in eax. See GRUB menu for Reboot / Shutdown / Firmware / Debug entries.
  2. Bootstrap sets up a 16 KiB stack, then pre-flight checks: Multiboot magic (ERR:M), CPUID support (ERR:C), long-mode support via extended CPUID (ERR:L). Any failure prints red ERR:X at 0xb8000 and halts.
  3. Identity-maps the first 1 GiB with 512 × 2 MiB pages (p4 → p3 → p2 in .bss), then enables PAE (CR4), long-mode enable (EFER.LME), and paging (CR0.PG).
  4. Loads the 64-bit GDT and far-jumps to long_mode_start — the CPU is now in 64-bit long mode.
  5. 64-bit entry inits COM1 serial, parses the memory map, then selects the console: if GRUB provided a 32-bit linear framebuffer (GOP on UEFI — mirrored to HDMI — or VBE on BIOS, requested via the multiboot tag), it maps it and prints with the built-in 8×8 font; otherwise VGA text. Then PIC remap, IDT install, sti. If the kernel command line contains prism (the GRUB “Prism Desktop” entry), the Prism GUI starts first and drops to the shell on Esc.
  6. shell_run takes over: prints bitos>, reads PS/2 scancodes via IRQ1 into a ring buffer, echoes + edits the line, executes help / ver / echo / clear / halt. Unknown commands are reported; halt stops the CPU.

Milestones 1–2 done and QEMU-tested (screenshot for v0.2, scripted typing + serial log for v0.3). Next milestone per roadmap: device drivers — PCI discovery first (the devices command below), then popular devices.

6. GRUB menu (no autoboot)

GRUB does not boot BitOS on its own — iso/boot/grub/grub.cfg sets timeout=-1, so the menu waits for a choice. (Set e.g. timeout=5 to auto-boot the default entry after 5 s.) Navigate with ↑/↓ + Enter, or the single-letter hotkeys.

EntryKeyEffect
BitOS v0.3 (default)bmultiboot2 /boot/kernel.bin → boots BitOS
Prism Desktop (GUI)pBoots BitOS with prism on the kernel command line → straight into the Prism desktop (BitWM); Esc falls back to shell
RebootrResets the machine (back to this menu)
ShutdownsACPI power-off (QEMU exits)
Reboot to Firmware SetupfUEFI firmware setup via fwsetup; on BIOS boot prints a notice and returns to the menu
BitOS v0.3 (Debug)dSame boot with GRUB debug=all output — pre-releases only, delete this entry for stable releases

All paths QEMU-tested: menu waits (empty serial), each entry boots/reboots/shuts down as listed, Debug boots despite debug output, firmware entry degrades gracefully on BIOS.

7. Shell commands

CommandEffect
helpLists all commands
verPrints BitOS v0.3 (long mode + keyboard + shell)
echo <text>Prints the text back (bare echo prints a blank line)
clearClears the VGA screen
devicesLists PCI hardware: bus:dev.func, vendor:device, class, vendor name
memShows usable RAM regions from the Multiboot2 memory map + total MiB
barsProbes PCI BAR0–5 (address/size/MMIO32/MMIO64/PIO) and maps + reads the first MMIO BAR as proof
usbxHCI bring-up (find → takeover → reset → rings → start) + per-port scan with speeds
gfxFramebuffer info + colour-bars test pattern (any key returns to console)
haltPrints halting. bye! and stops the CPU

Editing: printable characters echo, Backspace erases (never past the prompt), Enter runs, empty line reprompts. Everything is mirrored to COM1 serial — boot with -serial stdio to capture a session, or drive it scripted via QEMU sendkey.

9. Troubleshooting

  • grub-mkrescue missing — install grub-pc-bin + xorriso (Debian/Ubuntu) or equivalent. On Windows this only exists inside WSL2 — see Building on Windows.
  • nasm: command not found in WSL — run sudo apt install -y nasm. Native Windows NASM does not carry over into WSL.
  • ld / grub-mkrescue missing on native Windows — expected; they have no native builds. Use WSL2 (Option A) for link + ISO steps.
  • QEMU opens no window — make run tries -display none -serial stdio first, then falls back to graphical QEMU.
  • No response to typing — the shell needs IRQ1: check PIC remap ran, IDT gate 33 is installed, and you ran sti. In QEMU use -monitor stdio + info pic to inspect IRQ state.
  • Wrong characters from keyboard — driver expects scancode set 1, US layout. QEMU's default PS/2 emulation matches; real hardware with a different layout will differ.
  • Red ERR:M / ERR:C / ERR:L on boot — pre-flight check failed: bad Multiboot magic, no CPUID, or no 64-bit long mode (needs an x86-64 CPU; in QEMU use qemu-system-x86_64).
  • Red CPU FAULT #hh on screen — the same fault is also logged to serial as FAULT vec=.. err=.. rip=.. rsp=.. plus stack contents. Boot with -serial stdio and read the register dump instead of guessing.
  • Merge markers in README/LICENSE — if git status shows unmerged paths, resolve with git status → edit → git add → git commit before publishing.
